# Диагностика KartoshkaVPN на Windows

Скрипт `windows-proxy-health.ps1` **только читает** состояние системного прокси и владельца локального порта. Он не меняет реестр, DNS и сетевые маршруты. Запускайте его из обычного PowerShell от того же пользователя Windows, под которым работает KartoshkaVPN. Администратор не требуется.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\windows-proxy-health.ps1
```

Сравните результат до подключения, во время подключения и после штатного отключения. Если нужно проверить HTTPS-запрос через локальный прокси, выполните команду с параметром `-CheckInternet` во время активного подключения:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\windows-proxy-health.ps1 -CheckInternet
```

Эта дополнительная проверка обращается к `api.ipify.org` через локальный прокси и проверяет формат ответа, но не печатает IP. Для проверки смены внешнего IP сравните его самостоятельно в браузере до и после подключения. Сервис, к которому выполняется запрос, видит IP соединения.

Не присылайте ссылку на подписку, UUID, ключи, пароли, полный конфигурационный файл, IP-адрес или закрытые данные из логов. Диагностика не выводит эти данные намеренно, но перед отправкой любого вывода всё равно проверьте его. Если прокси использует другое приложение, не сравнивайте только состояние «включён»: важно сохранить именно предыдущие значения.

Если после аварии интернет не работает, не запускайте старые скрипты массового сброса без понимания последствий: они могут удалить настройки другого VPN или сети организации. Сначала сохраните вывод этой диагностики и обратитесь за дальнейшими действиями.
