## v0.9.7 — подключение при остаточном автоопределении и настройка XHTTP
- Исправлена блокировка запуска из-за остаточного бита автоопределения в
  WinINet. `FLAGS_UI` — производное значение: бит 8 может приходить из блоба
  `DefaultConnectionSettings` (9-й байт `09`), даже когда значения `AutoDetect`
  и `AutoConfigURL` в реестре отсутствуют. Теперь решение принимается по
  реальным значениям реестра и PAC-адресу: настоящий PAC URL по-прежнему
  блокирует запуск, а остаточный бит без адреса и без `AutoDetect` не мешает
  подключению. Предупреждение пишется в `app.log` и в «Диагностику», в
  интерфейсе показывается короткий текст без дампа RawValue.
- Восстановление после сеанса теперь корректно возвращает PAC-настройки,
  которые были до подключения, включая состояния «PAC + автоопределение».
  Добавлены тесты чистой таблицы состояний (ничего, только автоопределение,
  только PAC, оба) и Windows-тест реестра для автоопределения без PAC.
- XHTTP: параметры из query (`x_padding_bytes`, `no_grpc_header`, `xmux` и др.)
  сохраняются отдельно от `extra=JSON`. Новая настройка «Параметры XHTTP из
  ссылки» (по умолчанию включена) передаёт их ядру; при выключении используется
  только `extra=JSON`, как в 0.9.2. При подключении в «Логи» пишется итоговый
  блок `xhttpSettings` (path, mode, host, имена ключей extra) и версия ядра.
  Обе ветки проверены `xray run -test`.
- Кнопка «Скопировать диагностику» собирает `app.log`, последние 300 строк
  `core.log` и дамп настроек proxy Windows. Перед копированием маскируются
  UUID, пароли, `pbk`, `sid`, адреса серверов, URL подписок и внешние IP;
  локальные адреса proxy остаются читаемыми.
- Проверки: 95 JS-тестов (включая `xray run -test` на реальном ядре 26.10.31),
  Rust-тесты таблицы PAC и маскировки, Windows CI. Реальная перезагрузка Windows

## v0.9.5 — DoH по закреплённым IP

- DoH-провайдеры больше не разрешаются системным DNS: у каждого (Yandex,
  Cloudflare, Google, Quad9) встроены IPv4 bootstrap-адреса из документации,
  проверенные живым запросом 2026-11-19, и соединение закрепляется за ними
  (`ClientBuilder::resolve`). SNI и проверка сертификата остаются по имени.
  IPv6-адреса из документации добавлены, но в среде сборки нет IPv6-маршрута,
  поэтому живьём не проверялись. Клиент DoH не использует переменные окружения
  прокси (`no_proxy`), иначе имя провайдера снова ушло бы системному резолверу.
- Обнаружено и исправлено: Quad9 отвечает `505 HTTP Version Not Supported` без
  HTTP/2, Яндекс без HTTP/2 рвёт соединение. В сборку reqwest добавлена фича
  `http2`, после чего все четыре провайдера отвечают 200 по закреплённым IP.
- Встроенный DNS ядра переведён на IP-адреса (`https://77.88.8.8/dns-query`,
  `https://1.1.1.1/dns-query`): имён DoH-серверов в конфиге нет.
- DNS-запросы ядра помечены `dns.tag = "dns-query"` и явным правилом
  `inboundTag: ["dns-query"] → proxy` уходят через прокси-outbound. Проверено на
  ядре 26.10.31 с debug-логом: `from DNS accepted https://1.1.1.1/dns-query
  [dns-query -> proxy]`. В режиме «Авто» правило переводится на балансировщик.
- Список провайдеров и адресов вынесен в `shared/dns-providers.json`; Rust
  встраивает его при компиляции, `src/dns-providers.js` генерируется скриптом
  `scripts/gen-dns-providers.mjs`, тест сверяет сгенерированный файл с JSON.
- «Проверить DNS» показывает, какой сервер ответил, с какого IP и каким путём
  (закреплённый IP, кэш или системный DNS).
- Таймаут одного DoH-запроса — 6 с, все провайдеры опрашиваются параллельно:
  медленный провайдер больше не задерживает ответ.

## v0.9.4 — защита DNS и быстрое повторное соединение
- Главный экран: под кнопкой подключения два тумблера — «Защита DNS» (включена
  по умолчанию) и «Быстрое повторное соединение» (выключено). Те же тумблеры в
  «Настройках», состояние общее; есть aria-label и управление с клавиатуры.
- DNS до подключения: домены узлов и панель подписки разрешаются по DoH
  (RFC 8484, wireformat POST). Провайдеры: Yandex `common.dot.dns.yandex.net`
  (для .ru), Cloudflare, Google, Quad9; два первых опрашиваются параллельно,
  таймаут 3 с. Последний рабочий адрес кэшируется с TTL (до 600 с) и используется,
  если DoH не ответил. Откат на системный DNS только с уведомлением
  «Защита DNS не сработала, использован обычный DNS» и записью в «Логи».
  При подмене адреса сохраняются `server_name`/SNI и Host.
- DNS во время подключения: `builtinDns()` содержит только DoH-серверы, обычные
  UDP-резолверы убраны; .ru идёт на российский DoH, остальное — на запасной.
- «Быстрое повторное соединение» = TCP Fast Open. Включение при активном
  подключении не рвёт сессию: показывается «Применится после переподключения»
  и кнопка «Переподключить». После двух сбоев подряд опция выключается сама
  с сообщением и записью в «Логи».
- «Проверить DNS» в настройках: разрешает три имени через активный режим и
  показывает, какой сервер ответил.
- Проверено: 76 JS-тестов, `xray run -test` для DoH-конфига с TFO и без,
  Rust `cargo check` под Windows, шаг «Layout and scroll check».
  Не проверено в реальной сети: доступность DoH до подключения при
  заблокированных резолверах и поведение TFO у конкретного провайдера.

## v0.9.3 — исправления импорта и переключения

- XHTTP: параметры тонкой настройки читаются из отдельных query-ключей
  (`x_padding_bytes=100-1000` и другие из `EXTRA_ALIASES`, snake_case и camelCase),
  а не только из `extra=JSON`; значение из `extra` имеет приоритет. Для других
  транспортов такие ключи по-прежнему дают предупреждение. Проверено тестом и
  `xray run -test`.
- Hysteria2: `up`, `down`, `congestion` переносятся из ссылки в настройки узла,
  если заданы; по умолчанию не включаются. Проверено `xray run -test`.
- Автопереключение при сбое ядра стало настройкой «При сбое ядра»: только в пределах
  той же страны (по умолчанию), на любой сервер, не переключать. Переключение
  показывается уведомлением с названием узла и страной. Проверено тестами политики
  выбора узла и тестом `handleHealth` для режима «не переключать».
- CHANGELOG 0.9.2 исправлен: `content-visibility` убран из кода, строка о нём неверна.

## v0.9.2 — производительность и устойчивость

Измерения: `docs/perf.md`. Каждое изменение либо улучшало медиану задержки или
скорость не менее чем на 10 %, либо оставалось выключенной опцией.

- DNS: по умолчанию поведение 0.9.0 (ядро не резолвит имена само). Добавлена
  настройка «DNS»: встроенный DoH с кэшем — он включает IP-правила подписки для
  доменов и не отдаёт домены локальному резолверу. Замер по логам ядра: 0 обращений
  в режиме 0.9.0, 1 запрос + 4 попадания в кэш в режиме DoH.
- Health-check: проба `generate_204` раз в 30 с, перезапуск ядра после трёх провалов;
  после выхода из сна или смены сети — сразу и по одному провалу. Если перезапуск
  не удался, приложение переключается на следующий узел (не чаще раза в минуту);
  в 0.9.3 это стало настройкой «При сбое ядра».
- «Авто»: до шести узлов в одном конфиге, balancer `leastPing` и `observatory`,
  мёртвый узел выпадает из пула без участия пользователя.
- Опции тонкой настройки (по умолчанию выключены): sniffing, «предпочитать IPv4»,
  TCP Fast Open. Замер на стенде: TFO дал −7,7 % к TTFB, остальные — в пределах шума,
  порог 10 % не достигнут ни один вариант.
- Тест скорости в приложении: задержка, скачивание и отдача через активное
  подключение, адрес файла задаётся в настройках, результат сохраняется в статистике.
- Отзывчивость: одинаковый рендер больше не перестраивает DOM, каркас страницы
  строится один раз. 200 узлов: 2770 элементов, heap 3,0 МБ, переключение страницы
  53 мс (медиана). `content-visibility` пробовали и убрали: он менял высоту строк
  при прокрутке (в CI 1656 → 1569 px).

Не проверено на реальном Windows: сон, смена Wi-Fi/кабеля, поведение health-check
при обрыве у провайдера.

## v0.8.0
- Исправлена главная причина отказа импорта: ответ подписки разбирался по любым пробелам, поэтому названия вида «🇩🇪 Германия 1» разрывали ссылки на куски и весь импорт отменялся. Теперь ссылки делятся только по переводу строки и по началу схемы; несколько ссылок в одной строке тоже поддерживаются.

## v0.6.1

Примечание: приведённые ниже исторические заявления не являются подтверждением безопасности версии v0.6.1. В частности, ранняя реализация восстановления не гарантировала восстановление при аварийном завершении.

- Добавлен постоянный snapshot предыдущих Windows proxy-настроек в защищённой пользовательской папке приложения.

- Локальный порт `127.0.0.1:2080` проверяется вместе с PID запущенного дочернего `sing-box`.
- Добавлен мониторинг завершения процесса и событие ошибки для интерфейса.
- Перед запуском выполняется `sing-box check -c`.

- Импорт подписок теперь возвращает ошибки по строкам, а обновление сохраняет ручные узлы, избранное и пользовательские поля.
- Добавлены рабочие экраны настроек, статистики и логов.
- Добавлены Windows smoke-test в GitHub Actions и диагностический PowerShell-скрипт.
