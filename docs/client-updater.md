# Обновление клиента из GitHub

Раздел «Настройки → Обновление клиента» проверяет последний стабильный релиз
публичного репозитория `lifeisviolence-png/kartoshka-vpn` и, если версия новее,
скачивает установщик и запускает установку.

## Что происходит

1. `GET https://api.github.com/repos/lifeisviolence-png/kartoshka-vpn/releases/latest`
   с `Accept: application/vnd.github+json` и обязательным `User-Agent`.
   Draft и prerelease не принимаются.
2. Версия тега сравнивается с `app.package_info().version` по semver.
3. Для Windows выбирается `KartoshkaVPN_<версия>_x64-setup.exe`, для macOS —
   `KartoshkaVPN_<версия>_universal.dmg`. Имя должно начинаться с версии
   релиза; файлы с другим именем не подставляются.
4. Скачивается подписанный `SHA256SUMS.txt` (Windows) или
   `SHA256SUMS-macos.txt` (macOS) и его `.sig`. Ed25519-подпись сверяется с
   публичным ключом, закреплённым в приложении. Без подписи установка
   блокируется. Затем SHA-256 скачанного файла и размер сверяются с релизом;
   при несовпадении установка отменяется. Если GitHub API отдаёт
   `digest: sha256:…`, он также сверяется.
5. Скачанный файл сохраняется во временный каталог. Рядом создаётся helper —
   копия текущего исполняемого файла. Helper запускается с
   `--client-update-install`, ждёт завершения PID родительского приложения,
   устанавливает обновление и перезапускает приложение.
6. В Windows helper запускает NSIS-установщик с `/S`; если тихая установка
   недоступна, открывается обычный установщик. В macOS helper монтирует DMG,
   копирует `.app` во временный staging, заменяет текущий bundle и открывает
   его. Для записи в `/Applications` может быть запрошен пароль администратора
   через `osascript`.
7. Если VPN подключён, клиент сначала штатно отключает туннель и
   восстанавливает системный proxy, и только затем запускает helper.

## Границы доверия

Это **не** Tauri updater и не Apple Developer ID/нотаризация. Проверка Ed25519
защищает checksum-файл от подмены; SHA-256 защищает установщик от повреждения
или подмены при скачивании. Доверие к самому релизу всё равно опирается на
GitHub-аккаунт и контроль доступа к репозиторию. Приватный ключ Ed25519
должен храниться в GitHub Actions secret `KARTOSHKA_UPDATE_SIGNING_KEY`; в
репозитории есть только публичная половина. Если secret не настроен, workflow
выдаёт предупреждение, а клиент не устанавливает неподписанный релиз.

## Ограничения

- Нужен доступ к `api.github.com`; при исчерпании лимита GitHub API (60
  запросов в час с одного IP без токена) показывается ошибка.
- Обновление доступно только в Windows и macOS; browser preview только
  показывает пояснение.
- Обновление 0.9.8 → 0.9.9 нужно один раз установить вручную: в 0.9.8 этого
  раздела ещё нет.
- DMG подписан ad-hoc (`codesign -s -`), но не Developer ID и не нотаризован;
  Gatekeeper может предупредить при первом открытии.
- Helper сохраняет предыдущую версию до подтверждения запуска новой. Если
  новая версия не стартует, возвращается предыдущая. Журнал helper:
  `%TEMP%\kartoshka-update.log` в Windows или файл во временном каталоге macOS.
  Секреты туда не пишутся.

## Проверки

- Rust unit-тесты: semver-сравнение, выбор Windows/macOS asset, отказ при
  отсутствии checksum или Ed25519-подписи, проверка подписи, разбор SHA-256.
- JS: сборка Vite, i18n RU/EN, frontend-regressions, полный набор тестов.
- CI: macOS workflow собирает universal DMG и запускает Rust-тесты; Windows
  workflow собирает NSIS EXE и запускает Rust-тесты. CI не запускает реальную
  установку обновления и не проверяет живое подключение к VPN.
