# Что проверяет Windows CI и чего он не доказывает

Этот документ фиксирует границы автоматической проверки сборки `0.7.0`. Он нужен, чтобы статус «CI зелёный» не читался как «приложение проверено на любом компьютере».

## Как устроен прогон

Сборка выполняется на `windows-latest` в GitHub Actions. Тесты работают с настоящим `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` и с настоящим Xray-core, а не с заглушками: проверяются запись параметров WinINet, владелец TCP-портов 2080/2081 и фактический HTTP-запрос через локальный прокси. Раннер одноразовый, поэтому изменения реестра не выходят за пределы одной машины и одного запуска.

Из-за ограничений Job Object у службы GitHub Actions тестовый процесс запускается отдельной задачей планировщика. Это особенность стенда, а не продукта: приложение всё равно отказывается включать прокси, если watchdog остался в его собственном kill-on-close Job Object.

## Что именно проверяется

| Проверка | Что делает | Чего не доказывает |
| --- | --- | --- |
| Сборка и юнит-тесты Rust | Компиляция Windows-цели, тесты разбора snapshot, DPAPI, ограничения размера конфигурации | Поведение на конкретной версии Windows пользователя |
| Геоданные | Запуск `xray -test` с упакованными `geoip.dat` и `geosite.dat`, отказ при их отсутствии | Корректность маршрутизации для конкретной подписки |
| Отказ при чужом proxy/PAC/автоопределении | Три независимых теста: активный сторонний прокси, PAC-файл, автоопределение | Поведение сторонних VPN, которые меняют настройки асинхронно |
| Включение и восстановление | Реальная запись `ProxyServer`, `ProxyOverride`, `ProxyEnable`, `AutoDetect`, `AutoConfigURL`; проверка владельца портов; HTTP-запрос через `127.0.0.1:2080`; точное восстановление прежних значений | Работу через реальный сервер и реального провайдера |
| Аварийные сценарии | Падение GUI, ядра и watchdog; конфликт с другой программой; занятый порт; пропавший snapshot; осиротевший локальный прокси | Одновременное падение всех процессов, сбой питания, перезагрузку в момент записи |
| Установщик | Сборка NSIS, тихая установка во временную папку, наличие исполняемых файлов и геоданных | Запуск на машине с антивирусом, старыми версиями Windows и политиками домена |

## Что остаётся непроверенным

Реальная подписка и реальный сервер пользователя, скорость и стабильность канала, поведение антивирусов и SmartScreen (установщик не подписан), спящий режим и гибернация, одновременное завершение всех процессов, а также машины, где другой VPN-клиент меняет настройки в тот же момент. Эти случаи требуют отдельного ручного прогона на запасной машине или профиле Windows.

## Как читать результат

Зелёный запуск означает, что перечисленные сценарии отработали на чистом одноразовом раннере. Он не означает, что сборка безопасна на любом компьютере и с любой подпиской. Если запуск красный, установщик из этого запуска использовать не следует.
