# Что проверяет Windows CI и чего он не доказывает

Этот документ фиксирует границы автоматической проверки сборки `0.9.7`. Он нужен, чтобы статус «CI зелёный» не читался как «приложение проверено на любом компьютере».

## Как устроен прогон

Сборка выполняется на `windows-latest` в GitHub Actions. Тесты работают с настоящим `HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` и с настоящим Xray-core, а не с заглушками: проверяются запись параметров WinINet, владелец TCP-портов 2080/2081 и фактический HTTP-запрос через локальный прокси. Раннер одноразовый, поэтому изменения реестра не выходят за пределы одной машины и одного запуска.

Из-за ограничений Job Object у службы GitHub Actions тестовый процесс запускается отдельной задачей планировщика. Это особенность стенда, а не продукта: приложение всё равно отказывается включать прокси, если watchdog остался в его собственном kill-on-close Job Object.

## Что именно проверяется

| Проверка | Что делает | Чего не доказывает |
| --- | --- | --- |
| Сборка и юнит-тесты Rust | Компиляция Windows-цели, тесты разбора snapshot, DPAPI, ограничения размера конфигурации, формат отпечатка сертификата SHA-256 | Поведение на конкретной версии Windows пользователя; сам TLS-handshake для закрепления сертификата в CI не выполняется и проверен только вручную на Linux |
| Геоданные | Запуск `xray -test` с упакованными `geoip.dat` и `geosite.dat`, отказ при их отсутствии | Корректность маршрутизации для конкретной подписки |
| Отказ при чужом прокси | Активный сторонний прокси блокирует запуск, его настройки остаются нетронутыми | Поведение сторонних VPN, которые меняют настройки асинхронно |
| PAC и автоопределение | Два отдельных теста: запуск поверх PAC-файла и поверх включённого автоопределения без PAC проходит; после остановки значения восстанавливаются. Остаточный бит `FLAGS_UI` без PAC и без `AutoDetect` даёт предупреждение, но не блокирует запуск. На Windows Server 2025 бит автоопределения не сохраняется, тест печатает SKIP | Что именно присылает WPAD в конкретной сети; политики домена, меняющие WinINet |
| Включение и восстановление | Реальная запись `ProxyServer`, `ProxyOverride`, `ProxyEnable`, `AutoDetect`, `AutoConfigURL`; проверка владельца портов; HTTP-запрос через `127.0.0.1:2080`; точное восстановление прежних значений | Работу через реальный сервер и реального провайдера |
| Аварийные сценарии | Падение GUI, ядра и watchdog; конфликт с другой программой; занятый порт; пропавший snapshot; осиротевший локальный прокси | Одновременное падение всех процессов, сбой питания, перезагрузку в момент записи |
| Установщик | Сборка NSIS, тихая установка во временную папку, наличие исполняемых файлов и геоданных | Запуск на машине с антивирусом, старыми версиями Windows и политиками домена |

## Что проверено только вне Windows

Разбор подписок (включая названия с пробелами, неизвестные параметры, gRPC `gun/multi`, JSON-профили и ссылки Happ), частичный импорт с подтверждением, переключение языка и закрепление сертификата проверялись на Linux с реальным Xray-core 26.10.31: 17 тестов конфигурации, 10 фронтенд-тестов и 3 интеграционных теста (HTTP CONNECT, SOCKS5, Hysteria2 + Salamander, маршрутизация `.ru`). Совпадение отпечатка сертификата с `openssl x509 -fingerprint -sha256` проверено отдельно. Эти тесты не зависят от реестра Windows, но и не подтверждают поведение системного прокси.

## Покрытие 0.9.7
JS-тесты: 95 (конфигурация Xray с реальным ядром 26.10.31, включая обе ветки настройки XHTTP; импорт подписок; локализация; модель состояния; вёрстка и прокрутка). Rust: чистая таблица состояний PAC (ничего, только автоопределение, только PAC, оба), маскировка диагностики, DPAPI, snapshot. Windows: реестровые тесты активного чужого прокси, PAC, автоопределения без PAC, транзакции с реальным ядром и аварийные сценарии.
## Покрытие 0.9.0
К 10 тестам реестра и матрице аварийных завершений добавились JS-наборы: страны и флаги (7), модель состояния и слияние подписок (9), фронтенд (13), локализация (6), единая версия (1), конфигурация Xray (22, включая реальное ядро) и 3 интеграционных теста с локальными серверами. Они проверяют логику, но не заменяют реальное подключение на Windows: системный прокси, восстановление после перезагрузки и установку на чистые Windows 10/11 нужно проверять отдельно.
## Что остаётся непроверенным

Реальная подписка и реальный сервер пользователя, скорость и стабильность канала, поведение антивирусов и SmartScreen (установщик не подписан), спящий режим и гибернация, одновременное завершение всех процессов, а также машины, где другой VPN-клиент меняет настройки в тот же момент. Эти случаи требуют отдельного ручного прогона на запасной машине или профиле Windows.

## Как читать результат

Зелёный запуск означает, что перечисленные сценарии отработали на чистом одноразовом раннере. Он не означает, что сборка безопасна на любом компьютере и с любой подпиской. Если запуск красный, установщик из этого запуска использовать не следует.
