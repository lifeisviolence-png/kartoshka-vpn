Документ фиксирует, что именно проверено после выпуска 0.8.0, какими средствами и где границы доказательств. Версия 0.8.1 не публиковалась: изменения лежат в ветке `audit/0.8.1`.

## Уровни доказательств

| Уровень | Что это значит | Где выполняется |
| --- | --- | --- |
| A. Автотесты | Детерминированные проверки кода и парсеров, без сети и без Windows | Sandbox (Linux) |
| B. Локальная интеграция | Реальное ядро Xray 26.10.31, реальные сокеты, локальные тестовые серверы | Sandbox (Linux) |

Всё, что ниже, помечено одним из этих уровней. Уровень C на Server SKU не равен «проверено на Windows 10/11 у пользователя».

## 1. Правила маршрутизации Happ Plus

`parseRoutingProfile` теперь возвращает не только пригодные правила, но и список отклонённых: `{ index, reason, fields, target }`.

Поддерживаются: `domain`, `ip`, `port` (включая `80,443` и `8000-8100`), `network` (`tcp`, `udp`, `tcp,udp`), `source`, `domainMatcher`, `ruleTag`, `outboundTag` со значениями `direct`/`block`/`proxy`.

Отклоняются и **сообщаются**: `processName`, `processPath`, `user`, `inboundTag`, `protocol`, `attrs`, `balancerTag`, `vlessRoute`, `webhook`, `sourcePort`, `localPort`, `type != field`, `outboundTag` с чужим тегом (например `direct-2`), `ext:`-списки доменов, нечисловые порты, пустые правила. Глобальный `routing.domainStrategy` и блок `dns` не применяются и явно отмечаются.

В интерфейсе: предупреждения в окне «Результат импорта» с номером правила и полями, счётчик «Не поддержано правил: N» в настройках, отдельная строка про DNS.

Уровень A: `tests/xray-config.test.js` (19 тестов, включая профиль из 10 правил с 6 отклонёнными). Уровень B: конфиг с `network`/`source` проходит `xray run -test`. Уровень C: не применимо.

Чего не хватает: экспорт из настоящего Happ Plus от вашего провайдера. Пришлите файл — прогоню через парсер и покажу, какие правила приняты, а какие нет.

## 2. Hysteria2 + Salamander

Уровень B: тест поднимает настоящий Xray-сервер с Hysteria2, Salamander и самоподписанным сертификатом, клиент подключается с `pinSHA256` и скачивает страницу через HTTP CONNECT. Тест параметризован `HY2_HOST`: прогон на `127.0.0.1` и на адресе интерфейса (`169.254.0.21`) проходит, то есть путь не только через loopback.

Уровень C: нет. Реального удалённого сервера у меня нет, поэтому утверждать «работает через интернет» нельзя.

Что нужно от вас: узел Hysteria2 или ссылка подписки. Порядок проверки — `audit/check-real-server.md`.

## 3. Восстановление прокси после перезагрузки Windows

Уровень C: тест `partial` в Windows CI убивает процесс в середине записи реестра (мьютекс остаётся abandoned) и проверяет восстановление снимка при следующем запуске. Это имитация обрыва, а не перезагрузка.

Реальной перезагрузки не было. Для неё есть скрипт `audit/check-after-reboot.ps1`: снимает значения `ProxyEnable`, `ProxyServer`, `ProxyOverride`, `AutoConfigURL`, `AutoDetect` до подключения, после перезагрузки сравнивает и печатает PASS/FAIL.

## 4. Установка, обновление и удаление

Уровень C: workflow `.github/workflows/lifecycle.yml`, матрица `windows-2019`, `windows-2022`, `windows-2025`. Сценарий: установка 0.7.0 → проверка записи в реестре → установка сборки поверх (обновление) → проверка версии и файлов `xray.exe`, `geoip.dat`, `geosite.dat` → удаление штатным `uninstall.exe /S` → проверка, что файлы и запись реестра исчезли → чистая установка и удаление.

Результаты: Windows Server 2022 и 2025 — успешно (0.7.0 → 0.8.0, удаление, чистая установка и удаление). Windows Server 2019 — два прогона упали примерно через 13 минут, логи удалены вместе с отменённым запуском, причина не установлена.

Windows 10/11 в GitHub Actions недоступны: только Server 2019/2022/2025. Установка на домашнюю «десятку» или «одиннадцатую» остаётся ручной проверкой.

## 5. Английская локализация

Уровень A: `tests/i18n.test.js` — паритет ключей RU/EN, отсутствие кириллицы в английских значениях, отсутствие русских литералов в `src/main.js` и `src/desktop-bridge.js`, существование каждого `t('...')` и каждого кода ошибки парсера/конфига в обоих словарях.

Уровень B: headless-прогон `ui/audit.mjs` — все шесть экранов и оба диалога в EN, поиск кириллицы в отрендеренном тексте: пусто. Переключение RU→EN→RU сохраняется.

Известное ограничение: сообщения ядра на Rust (155 строк) остаются русскими. В EN-интерфейсе они помечаются «Core message (Russian only): …», чтобы не выдавать непереведённое за перевод. Полная локализация требует кодов ошибок вместо текста — это отдельное изменение протокола, не входит в 0.8.1.

## 6. Дизайн и работоспособность интерфейса

Уровень A: `git diff v0.7.0 -- src/styles.css` — только две добавленные строки для нового примечания о правилах; палитра, отступы и типографика не менялись.

Уровень B: тот же скрипт проверяет, что каждое действие `data-action` из DOM имеет обработчик в коде (0 необработанных), что нет ошибок в консоли (0), что работают поиск, избранное, переключение режима, языка, открытие и закрытие диалогов, и что в preview-режиме подключение даёт локализованную ошибку, а не падение.

## 7. CI не равен реальному подключению

Согласен и фиксирую: зелёный прогон доказывает, что код собирается, конфигурация валидна для ядра и реестр Windows обрабатывается правильно. Он не доказывает, что ваш сервер отвечает, что провайдер не блокирует QUIC и что скорость достаточная. Это закрывается только прогоном из раздела «Проверка на реальном сервере».
